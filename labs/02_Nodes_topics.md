## ROS узлы и топики

Вот и подошел черед познакомиться с первыми базовыми вещами ROS2 - **узлами**. Под узлом подразумевается программа, которая производит некоторые действия. Узлы соединяются **топиками**, через которые передают сообщения. Таким образом, получается нечто похожее на схемку типа графа. 


<p align="center">
<img src="../assets/ros2/ros2-node-communication.gif" width=500>
</p>

**❗Для начала знакомства необходимо запомнить важную вещь❗**

В ROS2 используется децентрализованная система обнаружения узлов на основе **DDS** (Data Distribution Service). Узлы автоматически обнаруживают друг друга, в отличие от ROS1, где сущесвует центральный "мастер", который следит за всеми процессами.


Начнем, чтобы что-то запустить, нужно воспользоваться утилитой запуска узла `ros2 run`, которая имеет следующее описание:
`ros2 run [pkg_name] [executable_name] [--ros-args additional args]`  
- *pkg_name* - имя пакета, в котором узел содержится  
- *executable_name* - имя исполняемого файла узла в пакете (обычно соответствует скрипту или бинарнику)
- *additional args* - дополнительные аргументы (рассматривается позже, в нашем случае используется с --ros-args для задания имени узла, namespaces и remapping)

Let's Go, создаем простейшую систему с топиком и узлами:

### 📄 Что будем запускать?

- Узел `talker` — каждую секунду публикует строку в топик `/chatter`
- Узел `listener` — читает сообщения из этого топика и выводит их

1. Открой **первый терминал**  
   ```bash
   ros2 run demo_nodes_cpp talker
   ```

→ каждую секунду будет появляться
> [INFO] [talker]: Publishing: 'Hello, world! 123'
>

2. Открой **второй терминал**  
   ```bash
   ros2 run demo_nodes_cpp listener
   ```
→ должен начать выводиться примерно такой текст:

> [INFO] [listener]: I heard: [Hello, world! 123]
> 
> [INFO] [listener]: I heard: [Hello, world! 124]
> ...
   
## Основные инструменты

### ros2 node

Открываем еще один терминал и начинаем анализ системы вместе с испытанием инструментов.

> 📌  Проверьте возможные команды утилиты `ros2 node --help`

Посмотрим список узлов в системе с помощью:

```bash
ros2 node list
```

Также можно посмотреть информацию о конкретном узле, например `/talker`:

```bash
ros2 node info /talker
```

Команда нам выдаст следующее:	

```
--------------------------------------------------------------------------------
/talker
  Subscribers:
    /parameter_events: rcl_interfaces/msg/ParameterEvent
  Publishers:
    /chatter: std_msgs/msg/String
    /parameter_events: rcl_interfaces/msg/ParameterEvent
    /rosout: rcl_interfaces/msg/Log
  Service Servers:
    /talker/describe_parameters: rcl_interfaces/srv/DescribeParameters
    /talker/get_parameter_types: rcl_interfaces/srv/GetParameterTypes
    /talker/get_parameters: rcl_interfaces/srv/GetParameters
    /talker/get_type_description: type_description_interfaces/srv/GetTypeDescription
    /talker/list_parameters: rcl_interfaces/srv/ListParameters
    /talker/set_parameters: rcl_interfaces/srv/SetParameters
    /talker/set_parameters_atomically: rcl_interfaces/srv/SetParametersAtomically
  Service Clients:

  Action Servers:

  Action Clients:

```

**Кратко** — что значит каждая часть вывода `ros2 node info /talker`


| Часть вывода              | Что это значит (простыми словами)                              | В данном случае у /talker                                      |
|---------------------------|----------------------------------------------------------------|----------------------------------------------------------------|
| **Subscribers**           | На какие топики узел **подписан** (что он читает/получает)     | Только системный топик `/parameter_events`                     |
| **Publishers**            | В какие топики узел **публикует** (что он отправляет)          | • `/chatter` — основная работа (Hello World)<br>• `/parameter_events` — изменения параметров<br>• `/rosout` — логи |
| **Service Servers**       | Какие **сервисы** узел предоставляет (на них можно позвонить)  | 7 стандартных сервисов для работы с параметрами + 1 для описания типов |
| **Service Clients**       | Какие сервисы узел сам **вызывает**                            | Никакие (пусто)                                                |
| **Action Servers**        | Какие длительные задачи (actions) узел может выполнять         | Никакие (пусто)                                                |
| **Action Clients**        | Какие длительные задачи узел сам запускает                     | Никакие (пусто)                                                |

**📄Самое важное в 3 словах:**

- Узел `/talker` в основном делает одну вещь — публикует строки в топик `/chatter`.
- Всё остальное — это автоматически добавляемая инфраструктура ROS 2: логи → `/rosout` и параметры → `/parameter_events` + куча сервисных методов

### ros2 interface

Также существует утилита `ros2 interface`, которая анализирует типы сообщений (интерфейсов)

В информации о топике мы видели поле типа сообщений, которые идут через этот топик

```
Type: std_msgs/msg/String
```

В типе можно видеть имя пакета типа `std_msgs` и само название `String`. Чтобы просмотреть, что содержит данный тип сообщения, воспользуемся командой


```bash
ros2 interface show std_msgs/msg/String
```

Результат:

```
string data
```

Как видно, данный тип сообщения содержит строковое поле `data`. Таким образом утилита анализирует информацию, связанную со строением (прототипом) сообщения, а не c самими данными в них.

## Создание ROS2 Publisher с использованием rclpy

Самое время познакомиться с возможностями написания узлов на языке Python в ROS2.
Сначала взглянем на код, который будем разбирать (в ROS2 рекомендуется использовать классовый подход для узлов):


```python

#!/usr/bin/env python3
import rclpy                        # это главная библиотека ROS 2 для Python
from rclpy.node import Node         # от неё будем наследоваться
from std_msgs.msg import String     # тип сообщения — просто строка

# ────────────────────────────────────────────────
# 1. Создаём класс — это и есть наш узел
# ────────────────────────────────────────────────
class Talker(Node):

    def __init__(self):
        # Даём узлу имя "talker"
        super().__init__('talker')

        # Создаём "почтовый ящик" — место, куда будем отправлять сообщения
        # Название топика → 'my_chat_topic'
        # Тип сообщения → строка
        # 10 — размер очереди (сколько сообщений можно временно держать)
        self.publisher = self.create_publisher(String, 'my_chat_topic', 10)

        # Говорим: "каждую 1 секунду вызывай функцию timer_callback"
        timer_period = 1.0          # 1 секунда = 1 Гц
        self.timer = self.create_timer(timer_period, self.timer_callback)

        self.get_logger().info("Узел talker запущен!")

    # ────────────────────────────────────────────────
    # 2. Эта функция будет вызываться каждую секунду
    # ────────────────────────────────────────────────
    def timer_callback(self):
        msg = String()                      # создаём пустое сообщение
        msg.data = f"Привет! Сейчас {self.get_clock().now().to_msg().sec}"  # пишем текст

        self.publisher.publish(msg)         # отправляем сообщение в топик
        self.get_logger().info(msg.data)    # показываем себе в терминале


# ────────────────────────────────────────────────
# 3. Главная функция — точка входа
# ────────────────────────────────────────────────
def main():
    rclpy.init()                    # начинаем работать с ROS 2

    node = Talker()                 # создаём наш узел

    try:
        rclpy.spin(node)            # "крутимся" и ждём событий (таймеров, сообщений и т.д.)
    except KeyboardInterrupt:
        pass                        # если нажали Ctrl+C — нормально выходим
    finally:
        node.destroy_node()         # убираем узел
        rclpy.shutdown()            # завершаем ROS 2


if __name__ == '__main__':
    main()

```

**Что здесь происходит?🙉**

- Мы создали класс **Talker** — это наш узел.
- При создании узла мы сказали:
>     «Меня зовут talker»
>     «Я буду отправлять сообщения в топик my_chat_topic»
>     «Каждую секунду вызывай функцию timer_callback»

- В **timer_callback** мы:
>     создаём сообщение
>     пишем в него текст
>     отправляем его
>     показываем себе в консоль, что отправили

- rclpy.spin() — это бесконечный цикл, который ждёт, пока таймер не сработает.


**Как превратить этот файл в запускаемый узел ROS 2?🙉**

1. Создай файл с именем **talker.py**
2. Положи его в папку **study_pkg/study_pkg/** (или как у тебя называется пакет)
3. Добавь в **setup.py** твоего пакета строчку (обращай внимание, если у тебя узел лежит в папке **scripts**, то путь нужно прописывать, включая ее) :
  
  ```python
  entry_points={
    'console_scripts': [
        'talker = study_pkg.talker:main',
    ],
    },
  ```
4. Собери и обнови окружение. Заменяй на название именно своего пакета!

  ```bash
  colcon build --packages-select study_pkg
  ```

5. Запусти узел

```bash
ros2 run study_pkg talker
```

Должен появиться вывод примерно раз в секунду:

  ```text
  [INFO] [talker]: Узел talker запущен!
  [INFO] [talker]: Привет! Сейчас 1734567890
  [INFO] [talker]: Привет! Сейчас 1734567891
  ...
  ```

## Создание ROS2 Subscriber с использованием rclpy

А теперь перейдем к написанию узла подписки.

### Что мы хотим сделать?

- Узел `talker` отправляет сообщения в топик `my_chat_topic` (как в предыдущем примере)
- Узел `listener` будет их ловить и выводить в консоль
  

```python
#!/usr/bin/env python3
import rclpy                        # главная библиотека ROS 2
from rclpy.node import Node         # от неё наследуемся
from std_msgs.msg import String     # тип сообщения — строка

class Listener(Node):

    def __init__(self):
        # Даём узлу имя "listener"
        super().__init__('listener')

        # Создаём подписку на топик
        # Название топика     → 'my_chat_topic'
        # Тип сообщения       → String
        # Функция-обработчик  → self.callback
        # 10 — размер очереди
        self.subscription = self.create_subscription(
            String,
            'my_chat_topic',
            self.callback,
            10)

        self.get_logger().info("Узел listener запущен и слушает топик!")

    # Эта функция будет автоматически вызываться каждый раз,
    # когда придёт новое сообщение
    def callback(self, msg):
        # msg — это пришедшее сообщение
        # msg.data — это строка внутри сообщения
        self.get_logger().info(f"Я услышал: {msg.data}")

def main():
    rclpy.init()                    # стартуем ROS 2
    node = Listener()               # создаём наш узел
    try:
        rclpy.spin(node)            # крутимся и ждём сообщений
    except KeyboardInterrupt:
        pass                        # Ctrl+C — нормально выходим
    finally:
        node.destroy_node()         # убираем узел
        rclpy.shutdown()            # завершаем ROS 2

if __name__ == '__main__':
    main()
```
**Краткое пояснение 🙉 :**

1. Создаём класс **Listener** — это наш узел.
2. В __init__ говорим:
  > «Меня зовут listener»
  > «Я хочу слушать топик my_chat_topic»
  > «Когда придёт сообщение — вызывай функцию callback»
3. В функции **callback** просто выводим текст, который пришёл.
4. **rclpy.spin()** — это бесконечный цикл, который ждёт сообщений и вызывает наш **callback**, когда они приходят.

**Как добавить этот узел в пакет и запустить?🙉**

1. Создай файл **listener.py**, положив его в папку **study_pkg/study_pkg/** (рядом с **talker.py**)
2. Добавь в **setup.py** ещё одну строчку (обращай внимание, если у тебя узел лежит в папке **scripts**, то путь нужно прописывать, включая ее). Должно получиться нечто похожее:
   
  ```python
        entry_points={
          'console_scripts': [
              'talker = study_pkg.talker:main',
              'listener = study_pkg.listener:main',
          ],
      },
  ```

3. Пересобери пакет и обнови окружение. Заменяй на название именно своего пакета!
   
  ```bash
  colcon build --packages-select study_pkg
  ```

4. Запусти оба узла в разных терминалах:
  
  **Терминал 1 (отправитель):**
  ```bash
  ros2 run study_pkg talker
  ```
  **Терминал 2 (получатель):**
  ```bash
  ros2 run study_pkg listener
  ```

Должен появиться примерно такой вывод в терминале **listener**:
  > 
  > ```text
  > [INFO] [listener]: Узел listener запущен и слушает топик!
  > [INFO] [listener]: Я услышал: Привет! Сейчас 1734567890
  > [INFO] [listener]: Я услышал: Привет! Сейчас 1734567891
  > [INFO] [listener]: Я услышал: Привет! Сейчас 1734567892
  > ...
  > ```

**Готово!**
У тебя работает связка: один узел отправляет → второй получает и показывает.

**Если всё работает — поздравляю, ты только что написал классическую пару publisher ↔ subscriber в ROS 2!** 🚀

## Имена узлов, пространства имён и переназначение топиков в ROS 2

Эти три механизма помогают правильно соединять узлы между собой, даже если они изначально писались для разных проектов.

### Имя узла (Node name)

Каждый узел в системе должен иметь **уникальное имя**.

По умолчанию имя берётся из кода (например, `super().__init__('talker')` → имя `/talker`).

Но при запуске можно задать **другое имя** с помощью аргумента:

```bash
ros2 run demo_nodes_py talker --ros-args -r __node:=my_special_talker
```

Тогда узел появится в системе как `/my_special_talker`.

**❗❗❗Важно:**
В ROS 2 два узла с одинаковым именем запуститься не могут — второй получит ошибку.

**Обычный запуск → имя /talker**

`ros2 run demo_nodes_py talker`

**Запуск с другим именем**

`ros2 run demo_nodes_py talker --ros-args -r __node:=speaker_1`

**Посмотреть все имена**

`ros2 node list`

### Пространство имён (Namespace)

**Пространство имён** — это просто **общий префикс**, который автоматически добавляется:

- к имени узла  
- ко всем топикам, которые этот узел создаёт или на которые подписывается

### Примеры

| Запуск команды                                      | Имя узла в системе      | Топик chatter становится     |
|-----------------------------------------------------|--------------------------|--------------------------------|
| `ros2 run demo_nodes_py talker`                     | `/talker`                | `/chatter`                     |
| `ros2 run demo_nodes_py talker --ros-args -r __ns:=/robot1` | `/robot1/talker`         | `/robot1/chatter`              |
| `ros2 run demo_nodes_py talker --ros-args -r __ns:=/left_arm` | `/left_arm/talker`       | `/left_arm/chatter`            |

### ❗Зачем это нужно?

Самые частые ситуации:

- Запустить две одинаковые системы на одном компьютере (например, левый и правый робот)
- Разделить узлы по смыслу: `/sensors`, `/navigation`, `/arm_controller`, `/vision`
- Избежать конфликта имён топиков между разными частями робота или между несколькими роботами

### 📝Практическое задание 1  

1. В первом терминале запустите talker в пространстве имён:

```bash
ros2 run demo_nodes_py talker --ros-args -r __ns:=/my_ns
```
2. Теперь посмотрите, как система видит узлы и топики:
  
  ```bash

- топик chatter теперь **/my_ns/chatter**

 Во втором терминале:

 ```

  В терминале `listener` ничего не выводится — сообщения не приходят.

**Почему так?**

  - talker публикует в топик `/my_ns/chatter`
  - **listener по умолчанию слушает топик `/chatter` → это совершенно разные топики → связи нет**
- 
1. Запускаем `listener` в том же пространстве имён

>   [INFO] [listener]: I heard: [Hello World 124]
>   ...

  **📎 Вывод:**

  ❕ Узлы видят друг друга и общаются только если их топики совпадают полностью (включая префикс пространства имён).

  ❕ Если узлы находятся в разных пространствах имён → их топики автоматически получают разные имена → они не соединяются, пока вы явно не сделаете remapping или не используете абсолютные имена.

### Переназначение топиков (Remapping)

**Маппирование** — это когда мы **меняем имя топика при запуске узла**, не трогая код.

Это один из самых полезных механизмов ROS 2. Благодаря ему можно соединять узлы, написанные разными людьми/командами, даже если они используют разные имена топиков.

#### Типичный пример из практики 📣

У нас есть два узла:

1. **Драйвер камеры** → публикует изображение в топик `/image_raw`
2. **Детектор объектов** → ожидает изображение на топике `/camera/rgb/image_raw`

**Вопрос: как их соединить, не меняя код ни одного из узлов?**

Ответ — **маппирование** при запуске:

```bash
ros2 run camera_driver camera_node --ros-args -r image_raw:=camera/rgb/image_raw
```

Теперь драйвер будет публиковать в `/camera/rgb/image_raw` — и детектор его увидит.

1. Запускаем `talker`, но меняем имя топика с `chatter` на `chat_topic`:

  ```bash
  ros2 run demo_nodes_py talker --ros-args -r chatter:=chat_topic
  ```

2. Запускаем `listener`, тоже переназначая `chatter → chat_topic`:

  ```bash
  ros2 run demo_nodes_py listener --ros-args -r chatter:=chat_topic
  ```

  Теперь они должны соединиться:

  - `talker` публикует в `/chat_topic`
  - `listener` слушает `/chat_topic`
  - в терминале `listener` появляются сообщения

3. Проверьте графически:
   
  ```bash
  ros2 run rqt_graph rqt_graph
  ```

Вы увидите, что **talker → chat_topic → listener** (без `/chatter` вообще).
